# Test protocol

ctune runs every test itself, so the user runs nothing by hand. Long tests run detached as systemd user units, so they outlive the agent session and hold a sleep lock while they run. When you start one, say what runs and when it ends; follow it with `test_status` and report the verdict when it arrives. `test_stop` stops one. Each result goes into the journal.

- **Screen** (every mem step, 25 min warm). `mem_test` screen runs stressapptest over the free RAM while memtest_vulkan heats the case, so the DIMMs warm up the way they do in a game.
- **Fabric screen** (FCLK steps, and the re-check after a BIOS flash). `mem_test` fabric runs the screen with NVMe reads for 90 min, then leaves the machine idle for 20 min. Random reboots at idle are the classic FCLK symptom.
- **TM5** (the timings pass, after the screens of a timing campaign are green). `mem_test` tm5 runs TestMem5 with the anta777 Extreme1 profile, its 3 cycles to the end, with the same GPU heat load. It takes as long as TM5 needs for the RAM it covers, and `minutes` only caps it. Install it once with `ctune mem tm5-setup`. Swap is off for TM5, so close large apps first. A run that runs out of memory, or that has not started testing after 5 min, ends `inconclusive`. A TM5 message box mid-test (a worker that died) is red, and the result quotes its text.
- **Sign-off** (end of a campaign, about 5 h 30 min plus TM5). `signoff` runs RAM, TM5, y-cruncher, the per-core Curve Optimizer cycle (mprime SSE, then AVX2), the GPU, a combined RAM, GPU and NVMe load and an idle soak. The 90 min GPU phase runs gpu-burn (FP32, FP64, tensor cores and load transients, every result checked), Quake II RTX on the RT cores, Unigine Superposition and Heaven for raster and tessellation, and memtest_vulkan; [the GPU reference](gpu-nvidia.md) explains each part. The user's normal use over the following days is the last check. `signoff` also writes each finished phase to the journal as a note, so a stop (verdict `stopped`) or a crash keeps the phases already done. An `inconclusive` phase (for example the GPU blocked by VRAM another app holds) does not stop the run; the sign-off ends `inconclusive` until that phase is re-run green.
- **Coverage.** A test takes the free RAM minus 1.5 GB, and `coverage_pct` reports the share of the total RAM it covered. Before a sign-off, ask the user to close large apps (browser, games) so coverage passes 80 %. A large `swapped_out_mb` means the test pushed the desktop into zram. The test is still valid; the desktop was only sluggish.
- **VRAM.** GPU tests and the GPU heat load need 2 GB of free VRAM. Below that, `gpu_test` refuses to start and `mem_test` runs without the heat load, and both name the processes holding VRAM. Ask the user to close them (an LLM server, a game) before a GPU step or a sign-off. When memtest_vulkan cannot allocate its buffer anyway (exit 68, no output), it tries up to three budgets, each 1 GiB smaller than the last; `alloc_retries` lists the ones that failed.
- **A quiet GPU.** Another program drawing on the GPU (a monitoring app's live graphs, a browser playing video, a game) takes GPU time from the test. Throughput drops by several percent at the same clock, and `clock_stretch` reads that as a stretched clock. Before a GPU test or a sign-off, idle GPU utilisation (`nvidia-smi`) should be about 0 %; ask the user to close what keeps it up.
- **One test at a time.** The GPU is shared, so a test refuses to start while another ctune test runs, whichever data directory it uses. For a development run, set `CTUNE_DATA` to a scratch directory and start it detached, so the campaign's own tests refuse to start beside it.
- **Quake II RTX, Superposition and Heaven** run in the screen and the sign-off. Install them once with `ctune gpu q2rtx-setup` and `ctune gpu unigine-setup`; without them both end `inconclusive`.
- **After a crash**, read the red record's kernel-line fields and run its `next_step` (the crashed boot's own log, which is not always `-b -1`), then the user checks the filesystem (on Bazzite and other ostree systems on btrfs: `sudo btrfs scrub start -B /sysroot` and `sudo ostree fsck`).
- memtest86+ needs a boot from USB, so ctune cannot run it. stressapptest finds overclocking errors faster. memtest86+ adds coverage of the memory the running OS holds, so offer it only when the user wants a full-coverage pass.
