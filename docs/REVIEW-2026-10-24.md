# RAM settings review — 5800X3D · B550 AORUS PRO · BIOS F16b (2026-10-24)

Baseline: `snapshots/20261024-181828_F16b/snapshot.md`. Method: live UMC registers (ZenStates-Core map) + SMU pm_table,
reviewed through 4 lenses (timing rules, voltages/FCLK, OC headroom, BIOS update), and every finding was then put
to an adversarial verifier. The full findings with sources are in `research/review_results.json` and `research/review_facts.md`.

## Verdict

Nothing is broken. DDR4-3733 CL14-15-15 with FCLK/UCLK/MCLK coupled 1:1:1 at 1867 MHz, on 4×8 GB single-rank B-die and a
daisy-chain board, is already close to the practical ceiling. AMD's spec for 4×1R is DDR4-2933, so this is +27%.
On a 5800X3D, the remaining tuning is worth about **0–1 % average FPS** in CPU-bound games, and about 0 % at
1440p/4K on the 3080 Ti. The 96 MB L3 hides most of the memory: PCGH measured only +1.9 to +3.5 % for the much bigger
step from 3200 CL16 to 3800.

**What this changes:**

## Capturing the trained ProcODT/RTT/CAD values (one reboot)

They live in ACPI NVS, the APOB at 0xA200000 and the AODT buffer. This kernel only allows reading there with `iomem=relaxed`.

1. **Boot once with `iomem=relaxed`.**
   - **One-time (preferred):** at power-on, press Esc or hold Shift to show the hidden GRUB menu. Press `e` on the Bazzite entry and append ` iomem=relaxed` to the `linux` line, then press Ctrl-X.
   - **Persistent alternative:** `sudo rpm-ostree kargs --append=iomem=relaxed`, then reboot. Remove it later with `--delete=iomem=relaxed`. This route also boots the staged Bazzite update.
2. Run `sudo python3 -I scripts/ram_snapshot.py --label "F16b iomem" --owner $(id -u):$(id -g)`.
   - It saves APOB (per-channel ProcODT/RTT/CAD/setup, MR0–MR6, the SPD/XMP of every DIMM), the AODT (VDIMM/VTT/VPP in mV), the EasyTune buffers, the setup variables and the decoded BIOS settings.
   - Only trust the AOD values if its tCL/tRCD/tRAS read 14/15/36.
3. Optionally, take F12 screenshots of Tweaker > Advanced Voltage Settings (the VCORE SOC and DRAM Voltage text) and PC Health. They resolve codes 64 and 55 to exact volts.

## BIOS update checklist (F16b → F19c, AGESA 1.2.0.12)

**Before flashing:**
1. Q-Flash → **Save BIOS to Drive**. F16b is no longer downloadable, so this is your only rollback.
   - Use a FAT32 stick, not the Tails stick and not the exFAT T5.
2. F12 screenshots (to the same stick) of:
   - Tweaker: VCORE SOC (note whether it's fixed or a DVID offset), CPU VDDP/VDD18, DRAM Voltage, **DRAM Termination**, DDRVPP.
   - Advanced Memory Settings, and all of its Memory Subtimings pages: Standard, Advanced, CAD Bus Setup, CAD Bus Drive Strength, Data Bus Configuration.
   - CPU/VRM LLC, PBO/Curve Optimizer.
   - AMD CBS → DF Common Options (DF C-states, APBDIS).
   - Settings → PC Health ("DRAM Channel A/B Voltage", "VCORE SOC", "DDRVtt A/B").
   - Note which fields are **Auto** and which are typed in.
3. Optional: boot once with `iomem=relaxed`, then rerun `ram_snapshot.py`. This captures ProcODT/RTT/CAD (and SPD via APOB).
   - Bazzite hides the GRUB menu: hold Shift or press Esc, press `e`, append the argument, then Ctrl-X.
   - It may return zeros. Only trust it if the AOD timings match 14/15/36.
4. Optional but recommended: 1 h stress test on F16b, so you have a proven baseline.
5. The staged Bazzite update (44.20261023, includes a ryzen_smu kmod rebuild) will apply on the same reboot. That's fine, but it's an extra variable.

**After flashing:**
1. Load Optimized Defaults.
   - On the fTPM "reset? Y/N" prompt, Y is fine: root is plain btrfs, and no TPM-sealed secret was found.
   - If the Bazzite boot entry is gone, pick the NVMe UEFI entry and shim will recreate it.
2. Re-enter only the fields that were manual. Leave Auto fields on Auto, especially DRAM Termination and DDRVPP.
3. Run `sudo python3 -I scripts/ram_snapshot.py --label "F19c" --owner $(id -u):$(id -g)`, then `scripts/ram_compare.py`.
   - Expected changes: SMU 56.74 → 56.78, microcode → 0xa201213. pm_table should stay 0x380905.
   - Programmed timings should be identical, and VTT should read about 70 counts.
   - tPHYRDL/tPHYWRL/tSTAG are trained values: note any change, don't pin them.
   - Also check `mokutil --sb-state`. If Secure Boot got enabled, ryzen_smu and /dev/mem access may be blocked.
4. Run a stress test and the MCE check (below). Then do ReBAR, then Stage A, then CO, each one separately.

## Testing on Bazzite (Linux equivalents of TM5/WHEA)

- **stressapptest (from a distrobox):** `stressapptest -M <MemAvailable - 1500> -s 3600 -W`. Lower `vm.swappiness` or turn zram off while it runs, so it tests DRAM rather than swap.
- **Other tests:** y-cruncher stress, OCCT for Linux (memory and Large AVX2), and memtest86+ overnight. For a heat soak, repeat one of them with the GPU loaded.
- **Errors (the WHEA-19 equivalent):** check these after each run. Wait at least 5 min, since corrected errors are polled every 300 s.
  - `find /sys/devices/system/machinecheck -name error_count -exec grep -H . {} + | grep -v ':0$'`
  - `journalctl -k -g 'Hardware Error|mce:'`
  - Any corrected MCE counts as a fail. rasdaemon (`rpm-ostree install rasdaemon`) keeps a permanent record.
- **After a crash:**
  - `sudo btrfs scrub start -B /sysroot` (`/` is a composefs overlay)
  - `sudo ostree fsck`
  - `journalctl -k | grep -iE 'btrfs.*(csum|corrupt|tree-checker)'`

## RAM fan (Corsair Dominator Airflow Platinum) — checked 2026-10-24

Evidence is in `research/ramfan_{H,F,V}.md`.

- **Header:** **SYS_FAN4** (IT8792E fan3/pwm3). It is on the right edge of the board below the 24-pin connector, the lowest of the three stacked headers SYS_FAN5_PUMP / SYS_FAN2 / SYS_FAN4. EC_TEMP1 is next to it.
- **Speed:** a fixed 51 % duty (130/255), about 2,130 RPM, which is about 58 % of the rated 3,700 RPM (≈12 CFM).
  - The BIOS SYS_FAN4 "Manual" curve sets this: on CPU temperature, flat 51 % from 20 °C, ramping only around 93–100 °C, with Fan Stop disabled.
- **CoolerControl's "RAM Fans Late" profile has no effect.** It asks for 0 % until the GPU hotspot reaches 80 °C.
  - The IT8792E's Gigabyte fan firmware rewrites the duty within about a second. The in-tree it87 driver can't disable that firmware.
  - CoolerControl's only effect is a 0 % pulse every ~31 s, which makes the RPM dip to ~1,830.
- **Airflow:** at the current fixed ~2,130 RPM it is very likely enough. This is unmeasured, because the DIMMs have no temperature sensor.
  - The CoolerControl profile would **not** be enough if it worked (0 % during memory-heavy CPU work). Target ≤ 40 °C on the DIMMs, with 45 °C as the danger line.
